ENTRY 001 The problem Rejected: walled garden

Where does your AI's memory actually live?

Ask the competitors. Their answer is a data center you don't control, a summary you can't read, and a delete button that doesn't prove anything. That's not memory — that's tenancy.

"To fully delete something ChatGPT may know about you, you'll need to delete every source." — OpenAI Help Center, Memory FAQ
Mem0's cloud memory is vector-based, not human-readable — no export format exists. — PAM memory-interchange survey, 2026
Claude's org-level kill switch permanently deletes all org memory — and owners cannot view members' memories. — Anthropic support docs, 2026

And the "self-hosted" alternatives stop at search. No ledger, no scoped keys per agent, no proof of erasure. The memory hub slot has been empty on purpose — governance is the boring part everyone skips. We didn't.

ENTRY 002 The mechanism vs. the field

One brain. Every agent knocks first.

Your memories live once — in Postgres and a vector store on your machine. Agents never "have" your memory. They request it through a scoped key, and the hub writes down the visit.

The six tools agents get: search_memory · get_memory · list_recent · add_memory · delete_memory · forget_memory — that's the entire surface. Anything more invasive would need a wider key, and you'd see it.

Salience, not landfill. Memories that get recalled grow stronger; ignored ones fade. The hub resurfaces what matters instead of hoarding everything forever.

ENTRY 004 Ninety seconds, start to agent Pass: first run

Two commands. Then give it an agent.

01 · Boot the hublite · 1 container
# whole hub: SQLite, in-process vectors
docker run -d --name orivory -p 8000:8000 \
  -v orivory-data:/data \
  -e OPENAI_API_KEY=sk-… \
  ghcr.io/twilightt1/orivory:lite
02 · Mint an agent keytoken shown once
curl -X POST localhost:8000/api/v1/agents \
  -H "Authorization: Bearer $YOU" \
  -d '{"name": "Claude Desktop",
        "scopes": ["memory:read",
                   "memory:write"]}'
# → {"token": "oa_9f3c…"} — keep it
03 · Hand it to your agentClaude · Cursor · OpenClaw

{ "mcp": { "servers": { "orivory": {
    "url": "http://localhost:8000/mcp",
    "transport": "streamable-http",
    "headers": { "Authorization":
      "Bearer ${ORIVORY_TOKEN}" } } } } }

ENTRY 005 A day with the hub Pass: capture → recall

The loop that keeps a second brain alive.

Second brains die quietly: capture is easy, retrieval never comes. The hub closes the loop with salience and scheduled resurfacing — the brain talks back.

07:00 · Mondaydigest lands

The brain writes to you first

A weekly digest of what you saved, grouped by topic, one question back: which thread do we go deeper on? You reply in your agent — no dashboard required.

09:14 · your editorcapture ≈ 0 effort

"Remember we moved to pgvector"

One sentence to the agent. add_memory fires with a title built to be searchable later. Import your old ChatGPT export once and everything from that life is here too.

11:30 · Cursorrecall, scoped

A different agent asks — with a narrower key

Cursor holds a memory:read-only token. It searches, quotes the memory with its title, and can't touch anything. The ledger now shows its visit next to Claude's.

16:45 · auditgovernance, on demand

"Which AI saw what?" is a table, not a mystery

Append-only ledger, filterable by agent. Something in there you regret? forget_memory cascades across rows, links and vectors — and hands back the receipt proving it.

nightlythe brain prunes itself

Salience decays. The useful stays on top.

Memories you actually recall grow stronger; stale ones fade below the fold. Your brain is a garden, not a landfill — no filing marathon required.

ENTRY 006 Run it your way Pass: 1 container

Lite for you. Full for everyone.

Most self-hosted tools make "simple" and "serious" mutually exclusive. Lite mode is the same code as the full stack — only the drivers swap.

Lite · your personal brain1 container
# SQLite + in-process vectors. Done.
docker run -d -p 8000:8000 \
  -v orivory-data:/data \
  ghcr.io/twilightt1/orivory:lite

# no Postgres, Redis, MinIO, workers
# ~1 user, agents welcome via /mcp
Full stack · team + UIcompose
# Postgres, Redis, Qdrant, MinIO,
# workers, Next.js UI — migrations
# run before the server starts
git clone github.com/twilightt1/orivory
docker compose up -d

# → localhost:3000 (UI)

Both modes speak the same MCP. Start lite tonight; when you want the web UI and team workspaces, move the volume — the memory is portable by design. Plus a GitHub Actions workflow builds the lite image to GHCR on every merge, so updates are docker pull.
