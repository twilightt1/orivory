1. Memory gen hiện tại của cộng đồng là gì?

Công thức chung: ghi bằng append → LLM trích fact/summary → nhúng vector (+ optional graph) → query top-k similarity + rerank → nhét vào prompt của model stateless. Chỉ khác chỗ lưu và chỗ tìm:
Supermemory
Cloud API + user profile + hybrid search + connector + plugin/MCP phủ rộng. Mạnh phân phối.
Claude-Mem
Hook ghi observation → worker tóm tắt → SQLite FTS5 (+ optional Chroma) → search → timeline → get_observations.
Mem0 / A-MEM / HippoRAG 2 / SimpleMem
Biến thể retrieval: quyết định ghi ADD/UPDATE/DELETE, note enrichment, triple+passage+PPR, chuẩn hóa unit + consolidation.
Orivory hiện tại
Postgres + Chroma hybrid + rerank, salience/decay, KG, scoped token + ledger + erasure receipt, MCP snippet→get, Lite 1-container.

Điểm chung yếu: ghi-append là chính; sửa / xóa lan / giải thích / thu hồi là phụ.

3. Định nghĩa lại memory next-gen

Next-gen = hệ nhớ sửa được, giải thích được, thu hồi được — với chi phí đo cả vòng đời. Không phải “nhớ nhiều hơn”, “graph to hơn”, “tự tiến hóa”. 5 tính chất tối thiểu:
  1. Evidence-first: raw + source ID là gốc bất biến; summary/profile là view dẫn xuất, luôn truy về nguồn.
  2. Correction hạng nhất: sửa lưu cùng subject/attribute/scope, hiệu lực từ khi nào, biết từ khi nào, nguồn nào thay nguồn nào. Mơ hồ → giữ cả hai + hỏi.
  3. Derived invalidation: view track nguồn dùng; nguồn đổi/xóa → đánh dirty, chặn phục vụ bản stale.
  4. Retrieval có biên: raw fallback luôn có; graph/LLM-rerank chỉ bật khi lỗi chứng minh cần + cap token/time.
  5. Governance đo được: provenance, scope, xóa cả dẫn xuất, receipt xác minh, stale rate, false-supersession, write+read cost.

Giới hạn诚实: chỉ bảo đảm các lần truy hồi sau qua Orivory; agent ngoài đã đọc/copy thì không thu hồi được — phải nói rõ trong skill.

6. Tech stack & latency: không đổi stack V1

Triển khai V1 = Lite-only: 1 container (SQLite + Chroma in-process + task eager + file upload), theo config.py:8-12, Dockerfile.lite, install.sh. Cài đặt mục tiêu: curl install.sh → MCP URL + token → cắm Claude/Cursor → nói chuyện. Không compose, không env matrix.

8. Goal & phục vụ ai

Người chính V1: solo dev, 1 máy, 2+ agent (Claude + Cursor trên cùng repo). Đau nhất: sửa cùng 1 fact N lần, mỗi agent một bản. Lát cắt fact cấu hình dự án sinh ra cho đúng người này.
Người sau: team nhỏ share memory không leak scope (workspace + scoped token + ledger đã có). Không phục vụ V1: enterprise SSO/SLA, end-user phổ thông, multimodal.
Goal đo được: sửa 1 lần → mọi agent sau trả đúng bản hiệu lực; stale ↓, false-supersession ≈ 0, cost vòng đời công khai, xóa thu hồi được. Không phải recall@k cao hơn Supermemory mọi giá.

10. Scope V1 · roadmap · risk · quyết định

IN V1
  • 1 fact type: cấu hình dự án theo thời gian
  • correct_memory + provenance ở get + state ở search + include_history
  • Fast-path skip-rewrite + fix timeline + trace theo stage
  • Lite-only 1 container; demo Claude + Cursor chung MCP
OUT V1 (cấm)
  • Bảng/DB/graph engine/PPR/microservice/fine-tune mới
  • 4-network Hindsight, consolidation đệ quy, self-optimizer
  • Dashboard/settings/graph-viz mới; team sharing; SSO/SLA
Roadmap: eval subset + 9 case nội bộ → đạt metric mới merge → spec lát cắt → implement → không công bố thắng ai. Mở rộng (graph bounded, consolidation, team) chỉ khi ablation chứng minh lỗi mục tiêu giảm không hồi quy accuracy/stale/cost/quyền.
Risk lớn nhất: resolve sai scope/thời gian còn tệ hơn không sửa. Mitigation: default giữ cả hai khi thiếu evidence; correction ≠ erasure; chặn stale đồng bộ, rebuild bất đồng bộ.
